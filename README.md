# onecx-chat-svc
OneCX Chat Backend Service

## Message persistence

HUMAN, ASSISTANT, and SYSTEM messages are stored as `TEXT` + `COMPLETED`
`CONVERSATION_ENTRY` rows, with role and user IDs retained on the entry.
Historical SYSTEM messages are also migrated as TEXT entries. The existing
chat message APIs keep returning the legacy Message shape in creation-date
order; retained message rows are hidden only when their IDs are represented by
entries.

The Liquibase `2026-11-12-typed-messages-to-conversation-entries` change adds
entry user and role metadata and deterministically backfills legacy
HUMAN/ASSISTANT/SYSTEM
messages by tenant, chat, creation date, and message ID. It reuses matching
terminal voice entries, rejects ownership, mirror, or ordering conflicts, uses
stable IDs and idempotency keys, and preserves the original rows for legacy
compatibility. Assistant replies
generated by asynchronous AI processing use a request-message idempotency key,
so retrying the same request cannot create a second reply entry.
